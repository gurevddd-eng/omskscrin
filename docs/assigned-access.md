# Assigned Access (Windows 10/11 Pro)

Жёсткий kiosk mode для Stella Kiosk.

Установка самого приложения — **через политики** (см. [gpo-deployment.md](gpo-deployment.md)). Ниже — режим киоска после того, как пакет уже на ПК.

## Подготовка

1. Убедитесь, что Stella Kiosk установлен политикой (MSI/MSIX) и на ПК есть WebView2.
2. Конфиг `%ProgramData%\StellaKiosk\kiosk.json` (или путь из политики) с полями:

```json
{
  "hostname": "patriotstela1",
  "kioskId": "patriotstela1",
  "serverUrl": "http://192.168.1.10:8080",
  "healthPort": 47821,
  "syncIntervalSec": 300,
  "idleTimeoutSec": 60,
  "heartbeatIntervalSec": 30,
  "appVersion": "0.1.0"
}
```

3. Учётка киоска, например `KioskUser` (без прав администратора) — из золотого образа или политикой.
4. В админке зарегистрирован тот же hostname.

## Настройка Assigned Access

1. Войдите под администратором (или примените скрипт/MDM-профиль киоска).
2. **Параметры → Учётные записи → Другие пользователи → Настроить киоск** (Assigned Access).
3. Выберите учётную запись `KioskUser`.
4. Укажите приложение **Stella Kiosk**.
5. Включите автоматический вход в `KioskUser` после загрузки (автологин) — через политику или `Winlogon` только на киоск-ПК.

### Автологин (кратко)

Через политики / `netplwiz` / реестр `Winlogon` (только на киоск-ПК, не на сервере).

## Выход техника

1. `Ctrl + Alt + Del`
2. Выйти из учётной записи киоска / сменить пользователя
3. Войти под администратором

## Проверка

- После перезагрузки открывается только киоск, без рабочего стола.
- Win / Alt+Tab недоступны посетителю (в рамках политики Assigned Access).
- После idle UI возвращается на главный экран.
- Обновление MSI политикой не ломает `kiosk.json` (конфиг вне каталога, который затирает инсталлятор).
